# Enforcement: чем правило отличается от намерения

[EN version](enforcement-en.md)

Скилл без внешних проверок — набор убеждений о том, что работает. Этот слой
отвечает на вопрос «откуда мы знаем, что правило соблюдается», и отвечает
числами, а не уверенностью.

## Шкала ступеней

Ступень определяется **внешностью проверки**, а не формулировкой. Слово
«ЗАПРЕЩЕНО» в тексте ступень не поднимает.

| Ступень | Механизм | Что это |
|---|---|---|
| 1 | Текст в скилле | Намерение |
| 2 | + размещение в начале и конце | Намерение с лучшими шансами |
| 3 | + наблюдаемый след в артефакте | Наблюдаемое соблюдение |
| 4 | + регрессионный тест с порогом k/n | Измеренное соблюдение |
| 5 | + внешняя проверка, которая падает | Спецификация |
| 6 | + архитектурная невозможность | Жёсткое ограничение |

Спецификация начинается с пятой. Всё ниже — намерение с разным качеством
доказательств. Две категории живут вне шкалы: `[эвристика]` — правило, у
которого признака нарушения нет и не будет, и `[дисциплина архитектора]` —
правило для человека, которое агентом не enforce'ится. Это нормально, если
помечено; ошибка не в том, что такие правила есть, а в том, чтобы считать их
спецификацией.

Честные карты по каждому правилу:
[project-dna](../skills/project-dna/ENFORCEMENT_MAP.md) ·
[architect-cc-workflow](../skills/architect-cc-workflow/ENFORCEMENT_MAP.md)

## Почему правила об артефактах дешевле правил о процессе

У `project-dna` профиль лучше: восемь правил уже на пятой ступени, потому что
предмет проверки — статичный файл. Файлы линтуются, поведение только измеряется.
Отсюда практический вывод: **новые правила стоит формулировать артефактно с
самого начала.** «Каждый инвариант имеет признак нарушения» проверяется грепом;
«агент действует осмотрительно» не проверяется никак.

## Линты

| Скрипт | Проверяет | Поднимает |
|---|---|---|
| [`dna_lint.py`](../skills/project-dna/harness/dna_lint.py) | структуру DNA: технологии, объём, признаки нарушения, негативные и числовые инварианты, блок ключевых инвариантов в конце | правила DNA до 5 |
| [`report_lint.py`](../skills/architect-cc-workflow/harness/report_lint.py) | Phase-end report: обязательные секции, запрет фраз самосертификации, наличие confidence markers, счётчики сигналов | §11, §12, §15.2 |
| [`signal_lint.py`](../skills/architect-cc-workflow/harness/signal_lint.py) | журнал сигналов: порядок по времени, отсутствие событий после BLOCK, бюджет тишины, совпадение счётчиков отчёта с журналом | §15.1, §15.2, §15.3 |

Все три без зависимостей, запускаются как `python3 <скрипт> <файл>`, exit 0 —
PASS, exit 1 — FAIL.

### Pre-commit

```bash
sh skills/project-dna/harness/install-hook.sh /path/to/repo
```

Хук срабатывает только если в коммит попал DNA-файл, обычные коммиты не трогает.
Кладётся целиком в `.git/hooks/` — отслеживаемое содержимое репозитория не
меняется. Существующий чужой хук не затирается, а вызывается первым.

**По умолчанию — предупреждение, не блокировка.** Это не осторожность, а вывод
из замера: DNA, написанные до введения признаков нарушения, линт не проходят
целиком, и блокирующий хук остановил бы работу разом во всех проектах.
Блокировка включается по проекту после миграции:

```bash
git config dnalint.blocking true
```

Репозитории на фреймворке `pre-commit` установщик не трогает — там
`.git/hooks/pre-commit` генерируемый; вместо этого печатает готовый фрагмент
для `.pre-commit-config.yaml`.

## Общение в процессе, а не в конце

Сигнал, доставленный в финальном сообщении, — не сигнал, а протокол вскрытия.
BLOCK ценен тем, что останавливает **до** действия. В headless-исполнении
финальный текст — единственный выход, и §15 без отдельного канала вырождается:
агент доводит работу до конца и лишь потом сообщает, что был BLOCK.

Поэтому сигналы пишутся в append-only журнал по мере возникновения:

```
2026-08-18T11:04:12Z  START      DevPrompt_07
2026-08-18T11:06:48Z  HEARTBEAT  шаг 2/5, прочитано 6 файлов
2026-08-18T11:09:31Z  NOTE       схема users не содержит email
2026-08-18T11:09:33Z  BLOCK      требуется ALTER TABLE, вне мандата
```

Строка пишется до действия, которого касается. BLOCK — последняя перед
остановкой. `signal_lint` проверяет это по времени, а не на слово, и сверяет
счётчики Phase-end report с журналом: отчёт, который пересказывает вместо того
чтобы отражать, детектируется.

## Регрессионный набор

[REGRESSION_SUITE.md](../skills/architect-cc-workflow/REGRESSION_SUITE.md) —
поведенческие тесты и baseline. Пять принципов, из которых два чаще всего
забывают:

- **Полнота по построению.** Каждый анти-паттерн имеет тест; изменение скилла
  без теста считается незавершённым.
- **Негативные тесты обязательны.** Без них набор поощряет гиперсрабатывание:
  скилл, блокирующий всё подряд, проходит все позитивные тесты. Механизм,
  срабатывающий слишком часто, неисправен так же, как не срабатывающий вовсе.

Запуск смоука:

```bash
sh skills/architect-cc-workflow/harness/run_smoke.sh
```

**Только из обычного терминала.** Внутри сессии Claude Code CLI отказывается
запускать вложенную сессию; скрипт это распознаёт и говорит прямо.

## Baseline — функция пары (скилл, модель)

При смене модели baseline недействителен целиком и перепрогоняется. При правке
скилла — недействителен для затронутых правил. Первый замер (2026-08-18,
Sonnet) это показал буквально: T-A-1 дал 2/3, конфликт §3 и §15 разрешили
правкой §3.6, пересчёт на новой версии дал 3/3 — и обе цифры остались в
таблице с указанием версии, потому что затирать замер новым значит терять
историю того, что изменилось и почему.

## Чего замер не показывает

Тест, который проходит, ещё не доказывает, что его обеспечил скилл. Для T-H-1
контроль без скилла и с пустым `CLAUDE.md` дал те же 3/3 — базовая модель ведёт
себя так же, и тест меряет её, а не протокол. Дискриминантность остальных
тестов не измерена.

Это не повод выбросить тест: он ловит регрессию, если поведение когда-нибудь
испортится. Но и не повод записывать его в заслуги скилла.

## Чего агент не может сделать за владельца

Признаки нарушения пробовали проставить агентами на одиннадцати существующих
DNA. Все одиннадцать прошли линт. Все одиннадцать провалили адверсариальную
проверку: 29 выдуманных признаков, 19 утрат уровня critical.

Причина не в качестве агентов, а в природе задачи. Признак нарушения — не
переформулировка инварианта, а доменное суждение о том, что в этом мире
наблюдаемо. Из текста он выводится синтаксически, и результат выходит
грамматически корректным и правдоподобным, но не связанным с предметной
областью: запрет становится условным, штатная процедура объявляется нарушением,
проверяемое состояние подменяется состоянием сознания аналитика.

Линт ловит отсутствие признака. Осмысленность признака он не ловит и не будет —
эта строка в карте стоит на первой ступени навсегда. Подробности:
`skills/project-dna/ENFORCEMENT_MAP.md`, раздел «Что показала массовая миграция».
