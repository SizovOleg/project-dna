# Пять режимов работы

[EN version](modes-en.md)

Project DNA имеет пять режимов. Каждый решает свою задачу в жизненном цикле проекта.

```mermaid
flowchart LR
    subgraph "Жизненный цикл"
        M1["1. Создание<br/>DNA"]
        M5["5. Создание<br/>RNA"]
        WORK["Разработка"]
        M2["2. DNA-<br/>аудит"]
        M3["3. Извлечение<br/>DNA"]
        M4["4. Мутация<br/>DNA"]
    end

    M1 -->|"Новый проект"| M5
    M5 --> WORK
    WORK --> M2
    M2 -->|"DNA устарел"| M4
    M4 --> M5
    M3 -->|"Существующий<br/>проект"| M5

    style M1 fill:#2d6a4f,stroke:#1b4332,color:#fff
    style M2 fill:#264653,stroke:#1a323d,color:#fff
    style M3 fill:#40916c,stroke:#2d6a4f,color:#fff
    style M4 fill:#e76f51,stroke:#c1440e,color:#fff
    style M5 fill:#52b788,stroke:#40916c,color:#000
```

---

## Режим 1: Создание DNA

**Когда:** Начинаешь новый проект.

**Триггеры:** *«создай DNA»*, *«начни проект»*, *«давай с начала»*

### Как это работает

```mermaid
flowchart TD
    START["Эксперт: «Создай DNA»"]
    
    START --> GATHER["Сбор контекста<br/><i>Миссия, сущности, ограничения,<br/>ценности, принципы, специфика</i>"]
    
    GATHER --> CRYSTAL["Кристаллизация<br/><i>Не формализация (записать что знаешь),<br/>а открытие (обнаружить что знаешь неявно)</i>"]
    
    CRYSTAL --> DRAFT["Черновик DNA<br/><i>По шаблону: 4 слоя</i>"]
    
    DRAFT --> TEST["Тест на технологии<br/><i>Убрать все названия —<br/>остался ли смысл?</i>"]
    
    TEST --> Q{"Прошёл?"}
    Q -->|Да| SAVE["DNA.md в корень проекта"]
    Q -->|Нет| CRYSTAL
    
    SAVE --> OFFER["Предлагает создать<br/>RNA и первый DevPrompt"]

    style CRYSTAL fill:#2d6a4f,stroke:#1b4332,color:#fff
    style TEST fill:#264653,stroke:#1a323d,color:#fff
```

### Пример диалога

```
Ты: Создай DNA для проекта анализа осадочных горных пород.

AI: Начнём с миссии. Зачем существует эта система?

Ты: Мы анализируем зёрна в шлифах — их размер, форму, 
    окатанность. Нужно автоматизировать то, что геологи 
    делают вручную под микроскопом.

AI: Понял. Несколько уточнений:
    1. Roundness и Circularity — это разные параметры или синонимы?
    2. Обучающая выборка — это разовый ресурс или постоянный актив?
    3. Что важнее — скорость обработки или точность классификации?

Ты: Roundness и Circularity — строго разные вещи! 
    Путать нельзя...
```

**Ключевой момент:** Вопрос про Roundness/Circularity — это кристаллизация. Эксперт знал, что они разные, но не сформулировал это как инвариант до вопроса AI.

## Режим 2: DNA-аудит

**Когда:** Хочешь проверить, не отклонился ли код от инвариантов.

**Триггеры:** *«DNA-аудит»*, *«проверь соответствие»*, *«что у нас за инварианты»*

### Как это работает

```mermaid
flowchart TD
    START["Эксперт: «Запусти DNA-аудит»"]
    
    START --> READ_DNA["Прочитать DNA.md"]
    READ_DNA --> STUDY["Изучить код, схемы,<br/>промты, тесты, конфиги"]
    
    STUDY --> CHECK["Для каждого раздела DNA<br/>оценить соответствие"]
    
    CHECK --> REPORT["Отчёт"]
    
    REPORT --> OK["✅ Соответствует"]
    REPORT --> VIOL["❌ Нарушение"]
    REPORT --> NOTIMPL["⚠️ Не реализовано"]
    REPORT --> UNDOC["🔍 В коде есть,<br/>но в DNA не описано"]

    style REPORT fill:#264653,stroke:#1a323d,color:#fff
    style VIOL fill:#e76f51,stroke:#c1440e,color:#fff
    style UNDOC fill:#e9c46a,stroke:#f4a261,color:#000
```

### Что отдаёт аудит

Только диагностику, **не предложения по исправлению**:

```
## DNA-аудит: SciProof

### Онтология
✅ Факт ≠ Утверждение — реализовано (таблицы facts, claims)
❌ Measurement ≠ Interpretation — склеены в одну модель
⚠️ Типизация фактов по источнику — не реализовано

### Деонтика  
✅ Оригиналы неизменяемы — immutable flag
🔍 Чанки не разрезают описания скважин — реализовано,
   но инвариант не записан в DNA

### Аксиология
✅ Полнота > скорость — timeout 60 сек
❌ Качество дистилляции — нет метрик в CI

### Требуют ручной проверки
- Корректность онтологических различений 
  (только эксперт может подтвердить)
```

## Режим 3: Извлечение DNA

**Когда:** У тебя есть проект, но нет DNA. Хочешь извлечь инварианты из того, что уже написано.

**Триггеры:** *«извлеки DNA»*, *«что у нас за инварианты»*, *«давай с начала»*

### Как это работает

```mermaid
flowchart TD
    START["Эксперт: «Извлеки DNA»"]
    
    START --> STUDY["Изучить ВСЕ документы проекта:<br/>код, README, CLAUDE.md, тесты,<br/>схемы БД, промты, комментарии"]
    
    STUDY --> FILTER["Для каждого решения:<br/>«Это верно для PostgreSQL,<br/>файлов И LLM с 10M контекстом?»"]
    
    FILTER --> Q{"Да?"}
    Q -->|Да| DNA_CANDIDATE["Кандидат в DNA"]
    Q -->|Нет| IMPL["Реализация — не DNA"]
    
    DNA_CANDIDATE --> GROUP["Сгруппировать<br/>по четырём слоям"]
    
    GROUP --> FORMULATE["Сформулировать<br/>без технологий"]
    
    FORMULATE --> REVIEW["Предложить<br/>эксперту на ревью"]

    style FILTER fill:#264653,stroke:#1a323d,color:#fff
    style DNA_CANDIDATE fill:#2d6a4f,stroke:#1b4332,color:#fff
    style IMPL fill:#95d5b2,stroke:#52b788,color:#000
```

## Режим 4: Мутация DNA

**Когда:** Понимание предметной области изменилось. Не код, не стек — само знание о мире.

**Триггеры:** *«обнови DNA»*, *«это решение изменилось»*, *«почему так устроено»*

### Как это работает

```mermaid
flowchart TD
    START["Эксперт: «Обнови DNA —<br/>Roundness теперь включает<br/>несколько методов измерения»"]
    
    START --> SHOW["Показать текущую<br/>формулировку в DNA"]
    
    SHOW --> PROPOSE["Предложить<br/>новую формулировку"]
    
    PROPOSE --> JUSTIFY["Обосновать: почему это<br/>мутация DNA, а не<br/>изменение реализации?"]
    
    JUSTIFY --> Q{"Эксперт<br/>согласен?"}
    Q -->|Да| UPDATE["Обновить DNA.md<br/>+ запись в таблицу версий"]
    Q -->|Нет| REVISE["Пересмотреть<br/>формулировку"]
    REVISE --> PROPOSE
    
    UPDATE --> AUDIT["Предложить<br/>DNA-аудит"]

    style JUSTIFY fill:#e76f51,stroke:#c1440e,color:#fff
    style UPDATE fill:#2d6a4f,stroke:#1b4332,color:#fff
```

### Важное правило

Агент **предлагает** мутацию, но **не коммитит** без согласия эксперта. DNA обновляется только владельцем проекта.

## Режим 5: Создание RNA

**Когда:** DNA готов, нужно создать enforcement-правила для конкретного стека.

**Триггеры:** *«создай RNA»*, *«создай harness»*, *«транслируй инварианты в правила»*

### Как это работает

```mermaid
flowchart TD
    START["Эксперт: «Создай RNA<br/>для Python/PostgreSQL/Claude Code»"]
    
    START --> READ_DNA["Прочитать DNA.md"]
    
    READ_DNA --> STACK["Определить стек:<br/>язык, БД, агент, CI"]
    
    STACK --> TRANSLATE["Для каждого инварианта:<br/>→ Проверка в стеке<br/>→ Тест / CI-правило<br/>→ Правило CLAUDE.md"]
    
    TRANSLATE --> GENERATE["Сгенерировать:<br/>RNA.md + Harness.md"]

    style TRANSLATE fill:#52b788,stroke:#40916c,color:#000
```

### Пример трансляции

| DNA (инвариант) | RNA (Python/PostgreSQL) |
|----------------|------------------------|
| «Факт ≠ Утверждение» | Модели `Fact` и `Claim` — разные классы. Тест: `test_fact_claim_separation()` |
| «Оригиналы неизменяемы» | `UPDATE originals SET ...` запрещён. SQL constraint: `BEFORE UPDATE RAISE EXCEPTION` |
| «Прослеживаемость» | `source_ref` NOT NULL в миграции. CI: `SELECT count(*) WHERE source_ref IS NULL = 0` |
| «Полнота > скорость» | Timeout 60 сек. Нет `LIMIT` без явного обоснования в комментарии |
